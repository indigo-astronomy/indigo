# ZWO ASI USB2ST4 generated migration

Status: complete, 2026-09-13. Baseline version: 0x02000006; completed version: 0x03000007. Windows is explicitly out of scope because no Windows SDK is available. Hardware tests are explicitly out of scope. The user-facing README remains unchanged.

## Existing behavior and findings

- One logical guider is attached per SDK ID after matching vendor `0x03c3` and a product ID returned by `USB2ST4GetProductIDs()`. Device names are `ASI USB-St4 Guider #<id>`. The driver exposes only standard connection plus RA EAST/WEST and DEC NORTH/SOUTH millisecond pulse properties.
- The API-2 hand-written driver owns device enumeration arrays, `connected_ids`, libusb hot-plug callbacks, delayed plug/unplug timers, an enumeration mutex and one SDK mutex per device. It is not generated and has no handler-queue ownership for guide changes.
- Open acquires the global device lock and calls `USB2ST4Open()` under enumeration/device mutexes; failed open rolls back the global lock. Close calls the SDK and unlocks globally but ignores close errors. A removed connected device can be closed both from detach and unplug cleanup depending on ordering.
- RA/DEC changes cancel the old completion timer before dealing with active hardware. Reversing an active axis starts the opposite relay without switching the old one off (`DRV-091`). A zero replacement cancels the timer but leaves the relay on and the property BUSY (`DRV-092`). Same-direction replacement also lacks explicit stop/restart semantics.
- SDK ON failures are logged but the driver still marks BUSY and schedules success. OFF failures are ignored, private relay state is cleared and OK is published while the fake relay remains asserted (`DRV-090`). Completion callbacks send redundant OFF to both axis directions and do not protect a replacement pulse from stale completion.
- RA and DEC use independent timers and SDK mutex serialization, but queue coalescing, same-axis replacement ordering, stale-finalizer ordering, simultaneous axes, unequal completion and one-axis failure isolation are not fully tested. Pulse timing has no recorded repeated 20–500 ms statistics.
- Disconnect synchronously cancels both timers, then closes without explicitly forcing every asserted relay off or reporting stop failure. Removal/shutdown lifetime must prevent SDK calls after close, property updates after detach, duplicate close and stuck BUSY.
- Hot-plug registration records `last_action = INIT` before registration succeeds, so retry falsely succeeds without a callback/device (`DRV-093`). Arrival schedules an untracked 0.5-second callback that can attach after SHUTDOWN (`DRV-094`). Product-list failure/retry, unsupported PID, invalid/out-of-range/duplicate SDK IDs, full capacity, multiple arrivals/removals and enumeration failure are not covered.
- The existing fake SDK models only one ID, one USB token, a single open flag and coarse one-shot failures. It cannot deterministically gate SDK calls, expose call order/history, model multiple devices/PIDs/IDs, inject per-direction/per-call failures, detect updates after detach, duplicate close, calls after close, pending callbacks or removal during a blocked operation.
- The current suite has nine fork-isolated cases, of which only three pass at baseline according to `indigo_test/CHANGES.md`; six failures reproduce `DRV-090`–`DRV-094`. It omits disconnected/connected property shape, driver info/version, boundary durations and item reset, same-direction replacement, both DEC reversal/zero paths, stale-finalizer gates, independent unequal axes, timing samples/statistics, disconnect/removal during pulses and blocked SDK calls, reconnect, repeated lifecycle, unsupported discovery, multi-device isolation and sanitizer coverage.
- `REFACTOR.md` and the future `.driver` do not exist in Xcode. Existing fake SDK/test files are already registered. No Visual Studio work is applicable. Generated source/header/main and version/copyright must remain synchronized, and properties documentation must point at the `.driver`.

## Atomic plan and progress

1. **Create the complete refactoring ledger — complete.** Record sources, SDK contract, all supported capabilities, known defects, lifecycle/concurrency risks, fake-SDK/test gaps, project/documentation obligations, exclusions and every atomic step before production edits.
2. **Register the ledger immediately — complete.** Added this file to the existing `guider_asi` Xcode group and validated the project before production edits; README and Windows files remain untouched.
3. **Capture the clean baseline — complete.** Recorded scoped status and SHA-256 hashes, built the unchanged archive/library/executable and fake-SDK test, and ran all nine fork-isolated cases: directions/cross-axis, open-failure retry and removal passed; reversal, zero stop, start failure, stop failure, registration-failure retry and shutdown with pending arrival failed as the six expected reproducers for `DRV-090`–`DRV-094`.
4. **Design the generated SDK hot-plug migration — complete.** Implemented generator `sdk { hotplug = true; vid = 0x03c3; discovery_retries = 6; ... }`, SDK-identity `unplug_match`, generated driver-wide discovery/connection queue and default five device slots without a `MAX_DEVICES` override. Discovery validates vendor/product, SDK counts and stable IDs, rejects invalid/duplicate IDs, preserves the legacy name and transfers each USB reference to exactly one attached device. No generator change was needed.
5. **Implement transactional SDK lifecycle — complete.** `asi_open()` now acquires the global lock, calls SDK open through the shared bounded SDK-call mutex and releases the lock on failure; generated connection ownership calls `asi_close()` only after a successful open. Close is logged and balances the lock once. Per-device mutex/timer/enumeration scaffolding was removed; the sole mutex serializes the vendor library across independent per-device queues.
6. **Implement an owned per-axis pulse state machine — complete.** RA and DEC separately track the active direction and monotonic deadline. SDK ON success is required before BUSY publication; named priority finalizers stop only the owned direction and publish zero/OK or ALERT. Replacements and zero requests first stop the active relay, item values/targets are cleared deterministically, OFF failure retains ownership for a later recovery attempt, and deadline rechecks prevent early stale completion. An explicit generation counter is unnecessary: a finalizer always evaluates the current axis owner/deadline, so an old callback either reschedules for the replacement deadline or becomes a no-op after that owner stops.
7. **Implement replacement and concurrency semantics — complete.** Same/opposite replacements stop before restart and handle both stop and start failure. The two axes retain independent state and properties while every SDK call is serialized; there are no waits or sleeps in driver callbacks. Rapid requests are processed through queue ordering from the latest copied property values. No running property handler or finalizer is synchronously cancelled during replacement; stale finalizers compare the current axis deadline, reschedule if early and become harmless after the current owner stops. Each asynchronous `on_change` passes its named `_finalizer` explicitly, so the generated handler correctly omits its synchronous OK/update epilogue and the operation publishes exactly its owned start/error/completion updates.
8. **Implement disconnect, removal and shutdown safety — complete.** Generated disconnect cancels queued work before `on_disconnect`, which explicitly stops both active axes before close. Generated SDK retry records replace the untracked arrival timer; registration failure resets action state, shutdown deregisters, cancels retries, drains the driver queue and releases references. Connected shutdown remains rejected. Fake lifecycle assertions currently show no SDK call after close, update after detach or duplicate close.
9. **Complete fake SDK discovery/lifecycle modeling — complete.** The fake now supports eight independently configured USB tokens/PIDs/stable IDs, presence/open/relay state, product/GetNum/GetID/open/close/lock/registration failures, invalid and duplicate identities, unsupported products, arrival/removal, exact timestamped events, reference/lock/attach accounting and detectors for duplicate close, invalid/post-close calls and post-detach updates.
10. **Complete fake SDK pulse/race modeling — complete.** Added timestamped per-device ON/OFF events, relay masks, one-shot ON/OFF failures and deterministic gates for enumeration, open, close, ON and OFF. Gates use bounded test waits and are unconditionally released during cleanup; lifecycle counters expose stale work and invalid ownership.
11. **Cover discovery and transactional connection — complete.** Passing isolated scenarios cover INFO/version and disconnected/connected property shape; supported/unsupported PID; product-list and registration retry; GetNum/GetID delayed retry; invalid and duplicate IDs; two-device identity/isolation/removal in both connection orders; default capacity overflow and automatic recovery after a slot is freed; global-lock/open/close failures, exact lock balance and reconnect. SDK/libusb counters verify ownership.
12. **Cover directions, units and completion — complete.** Passing tests cover all four SDK directions, public millisecond durations at 20/100/500 ms representatives, 0–10000 ms metadata, opposed-item priority, zero no-op, BUSY, exact per-direction ON/OFF counts, item reset and OK. Injected ON/OFF failures publish ALERT and the next request recovers.
13. **Cover replacement and axis independence — complete.** Passing cases cover RA opposite replacement, DEC same-direction replacement, active zero stop on both axes, a rapid queued DEC burst with latest-request completion and optional pending-request coalescing, stale RA finalizer versus a longer replacement, simultaneous unequal RA/DEC completion and one-axis OFF failure without clearing the other axis. The fake additionally fails any opposed-relay overlap.
14. **Cover lifetime and recovery races — complete.** Passing cases cover active disconnect/reconnect/pulse, active removal/re-arrival/pulse, removal of one of two devices, blocked ON followed by queued disconnect, blocked OFF followed by removal, connected-shutdown refusal, repeated accepted SHUTDOWN/INIT, and shutdown with gated queued discovery. Every cleanup asserts zero attached devices, locks and USB references plus no post-close I/O, post-detach update, duplicate close or deadlock.
15. **Add guider timing measurements — complete.** Added a separate benchmark with one discarded warm-up and five measured samples for each NORTH/SOUTH/EAST/WEST × 20/100/250/500 ms combination. It measures fake-SDK ON-to-OFF edges and reports signed error, percent, min/mean/median/p95/p99/max, standard deviation and maximum absolute error without host-dependent pass thresholds. ## Acceptance boundary

Completion requires every applicable Guider Driver Test Standard row to map to named passing fake-SDK tests with fresh revisions and bounded waits. Because this is a standalone SDK guider, shared camera/mount acquisition and guide-rate scenarios are not applicable. Generic framework numeric validation is not duplicated. The fake SDK establishes driver translation, state, queue, timing and lifetime behavior, not real USB electrical output, SDK binary internals, embedded macOS HID run-loop behavior, physical hot-plug, hardware timing or Windows support.
