# Scripting Agent — automated coverage

Date: 2026-09-14. Scope: user-requested complete behavioral test coverage of `agent_scripting`, including the long-text/configuration crash regression. This is a test implementation and audit, not a generator migration. Production agent version at entry: `0x0300000B`; baseline HEAD `5dd7a9415`.

## Baseline and architecture

The handwritten, platform-independent agent exposes one device plus one bus client. It embeds the bundled Duktape engine and `boot.js`; no vendor SDK, serial transport or physical device is involved. Six fixed script-management properties control immediate execution, saved scripts, execution selection, deletion and load/unload hooks. Up to 128 user-script records, 126 cached script-defined properties and 32 timers are stored privately. Standard hidden CONFIG/PROFILE properties provide framework persistence. Scripts define/redefine/update/delete text, number, switch and light vectors, change peer properties, receive all five vector types, save/populate BLOBs, use astronomy/time conversions, log and schedule timers.

JavaScript execution and callbacks use a recursive mutex. Script-originated bus changes and messages are queued; timers execute callbacks through the framework. Configuration serialization/parsing and property ownership are shared framework behavior. Audit focus includes queued property lifetimes, exception recovery, source buffer ownership, script/property capacities, reentrant callbacks, timer cancellation, and load/unload ordering. The recent bus fix is already present. Existing `REVIEW.md` changes from the preceding commit review must be preserved.

References read: root and driver/test instructions; DEVELOPMENT, DRIVER_DEVELOPMENT_BASICS, MAKEFILES and DRIVER_TESTING_RULES; the driver README, C source, boot.js, public names, Makefile.drv, existing Configuration Agent test harness and its Makefile integration. No driver-specific tests existed at entry (`MIGRATION_STATUS.md`: 0 / 0). Camera/mount/wheel/guider hardware class checklists are not applicable to this software agent; the shared lifecycle, state, persistence, failure and concurrency rules are applicable.

Hardware decision: no physical hardware tests. Use real Duktape, the public bus and scripted in-process peers. Redirect configuration lookup and BLOB download responses in the test-only build; never open network sockets or write user configuration. Exercise init/shutdown/reinit, not dynamic library unloading. macOS arm64 execution and arm64/x86_64 compilation are available; Linux/Windows execution is unavailable.

## Found defects and fixes

The audit and new regression suite found the following production defects. The fixes raise `DRIVER_VERSION` from `0x0300000B` to `0x0300000C`.

- Source audit, regression protected: invalid BLOB objects could crash the agent. `indigo_save_blob(path, {})` and `indigo_populate_blob({})` read `item->blob` after the missing JavaScript `reference` had produced a null `indigo_item *`. Both bindings now return `undefined` before dereferencing a null reference. The BLOB test covers valid download/save, download failure, file-open failure and both invalid-object calls.
- Source audit, regression protected: script-originated text changes truncated long values. `change_text_property()` copied through the fixed-size `INDIGO_VALUE_SIZE` buffer even though INDIGO text items support dynamically allocated raw values. It now uses `indigo_set_text_item_value()`. The regression sends an 8,192-byte peer-property value and checks the complete request received on the bus.
- Source audit, regression protected: an invalid UTC string silently became a delay derived from a zeroed `struct tm`. `utc_to_delay()` ignored the result of `parse_utc()`. It now returns a Duktape error when parsing fails; the test verifies the error and subsequent interpreter recovery.
- Reproduced by the configuration lifecycle tests: on-load hooks raced configuration restoration. The CONFIG handler started hooks immediately after requesting an asynchronous load, so saved scripts and hook selections could still be absent. Hook execution now runs through `on_load_finalizer()`, which waits while CONFIG is BUSY, propagates configuration and script failures as ALERT, and executes synchronously when no wait is needed. Shutdown explicitly cancels this identified pending finalizer before destroying Duktape state.
- Reproduced by explicit repeated load: configuration restoration treated already present saved scripts as duplicate user additions. Requests from `CONFIG_READER` now update the matching saved script body in place and acknowledge the restore. ADD, ON_LOAD and ON_UNLOAD handlers also skip recursive configuration saves while restoration holds the config mutex. Reinitialization and explicit load tests cover ordering, idempotent restore and long script persistence.
- Reproduced by public-property tests: script deletion did not acknowledge success and gave no failure result for an unknown name. The DELETE property now starts in ALERT, changes to OK only after a match, clears the submitted name and always publishes a final update with `Script not found` on failure. Both paths have dedicated tests.
- Source audit, regression protected: a saved script could be renamed to an empty or already used display name, leaving ambiguous execute/delete selections. Rename handling now validates the requested name before copying property values and publishes ALERT without modifying the script. The suite verifies both rejection cases and recovery with a valid rename.
- Source audit, regression protected: failed on-load and on-unload scripts were reported as successful. Both hook paths now aggregate `execute_script()` results, continue through the selected hook list, publish ALERT on any failure and remain usable afterward. Dedicated failure/recovery tests cover both lifecycle phases.
- Reproduced by the `boot.js` cache test: whole-device deletion never removed the device from the cache. The INDIGO delete event represents this with an empty C property name, while `boot.js` expects JavaScript `null`; the C callback always pushed a string, making the whole-device branch unreachable. It now maps an empty property name to `null`. The regression deletes the peer device and verifies that `indigo_devices` no longer contains it.
- Reproduced under AddressSanitizer: the documented 128-script limit caused a heap buffer overflow before it was reached. EXECUTE allocated only 126 items, while ON_LOAD and ON_UNLOAD allocated 128 items including their permanent `New script` item; adding the 127th/128th script wrote beyond those buffers. The properties now allocate 128 execution items and 129 hook items. The capacity test fills all 128 slots, verifies rejection of the 129th script and slot reuse; ASan verifies the corrected bounds.

Findings reproduced while implementing the corpus:

- Reproduced by a quoted-message execution: public helpers embedded text arguments directly between double quotes in generated microsteps. A quote, backslash or control character in a message, evaluation snippet, device/agent name, FITS value, directory or file template could therefore make the microstep invalid or change the code executed. Impact: valid sequence input could fail at runtime, and crafted text could inject another sequencer operation. Root cause: hand-built JavaScript source lacked string serialization. Fix: every textual microstep argument is serialized with `JSON.stringify()`; representative single-argument, two-argument and optional-overload paths are covered.
- Reproduced by executing the documented UTC form of `break_at()`: the constructor converted the string to a numeric timestamp for its warning check but embedded the original unquoted string in the microstep. Impact: date punctuation was interpreted as JavaScript subtraction instead of a UTC timestamp, so the cutoff was wrong. Root cause: the converted local variable was not used. Fix: embed the converted numeric timestamp and cover UTC-string and numeric forms.
- Reproduced with a deliberately missing selected agent: a microstep exception escaped `execute_next()` and the native timer callback, leaving the sequence and active step permanently Busy. Impact: missing devices and other unexpected JavaScript errors bypassed all documented abort/continue/recover policies and required manual reset. Root cause: the dynamic microstep `eval()` had no exception boundary; low-level setters also dereferenced a missing device before their existing missing-property check. Fix: catch microstep exceptions, route them through `failure()`, and make text/number/switch setters treat a missing device like a missing property. Regressions cover all three policies and recovery-without-point.
- Reproduced by inspecting the public control properties: `AGENT_ABORT_PROCESS`, `AGENT_PAUSE_PROCESS` and `SEQUENCE_RESET` were published with AnyOfMany instead of OneOfMany. Impact: clients received the wrong switch rule for action controls. Root cause: Sequencer passed `OneOfMany`, while the native binding accepts the canonical `ONE_OF_MANY`; unknown rule text falls back to AnyOfMany. Fix: use canonical rule constants and assert every public property's type, permission, rule and item count.
- Reproduced by UBSan in the simulator guiding scenario: the Guider Agent divided a newly snooped CCD frame by zero before its binning values had arrived, then converted infinity to `int`. Impact: undefined behavior during device discovery could corrupt the cached frame dimensions used for selection validation. Root cause: frame and binning properties arrive independently, but the selection reset assumed positive binning was already cached. Fix: defer the derived dimensions and selection reset until both bin values are positive. The same end-to-end guider scenario is the regression. This raises the Guider Agent version from `0x0300002E` to `0x0300002F`.
- Reproduced by the full Guider Agent regression corpus after the Sequencer-triggered Guider fix: the previously recorded DRV-130 RA-only dithering path projects the requested offset with `x = magnitude / (cos(angle) + tan(angle))`, which does not preserve the requested magnitude. Impact: the actual dithering distance depends incorrectly on camera angle. Root cause: the projection formula mixes normalized-axis and slope terms. The proposed `x = magnitude * cos(angle)`, `y = magnitude * sin(angle)` fix was declined for now and remains commented in the source. DRV-130 awaits manual approval: the existing `dither RA projection preserves magnitude` case must continue to record the known failure and must not cause an automatic code fix during future Guider Agent testing.
