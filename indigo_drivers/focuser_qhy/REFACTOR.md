# QHY Q-Focuser generated migration

Status: complete, 2026-09-13. Baseline version: 0x03000006; migrated version: 0x03000007. Hardware tests are explicitly out of scope. The user-facing README remains unchanged.

## Sources and protocol confidence

- Repository guidance: root and `indigo_test/AGENTS.md`, driver-development basics, generator migration guide, serial-simulator contract, common driver-testing scope and focuser standard.
- Production sources: the hand-written driver, public header, standalone wrapper, existing Visual Studio project; the host PTY simulator; the current integration test; property, simulator, test, Makefile, Xcode, Windows and migration records.
- Driver-specific repository documentation is the user-facing README. It identifies the QHY Q-Focuser, supported platforms and a firmware caveat but contains no wire-protocol specification; it must remain byte-identical.
- The official QHYCCD product/user-guide page documents Standard and High Precision variants, USB 2.0 Type-C, 5 V/12 V power, external temperature sensing, movement, current/custom position, limits, reverse, high-speed and keep-force behavior. The official download page publishes ASCOM drivers, but the research found no manufacturer JSON wire-protocol document. Protocol bytes and command IDs below are therefore implementation-derived compatibility, not independently documented facts.
- Requests are brace-delimited JSON objects at 9600 baud or over `qfocuser://`/TCP port 8080. Implemented commands are 1 version, 3 abort, 4 temperatures/voltage, 5 position, 6 absolute target, 7 reverse, 11 sync, 13 speed and 16 hold current. Replies use `idx`; command 1 returns `version`/`bv`, command 4 returns milli-degree `o_t`/`c_t` and decivolt `c_r`, and command 5 returns `pos`.
- Simulator validation can prove command formatting, parsing, state transitions, queue ownership, timeout/recovery and compensation decisions. It cannot certify undocumented firmware grammar/timing, physical direction, load/travel/limit safety, sensor accuracy, motor current semantics, USB bridge behavior, network deployment or real platform runtime.

## Existing behavior and findings

- The driver exposes one absolute focuser with additional instances. It supports absolute GOTO and SYNC, inward/outward relative motion translated to absolute targets, abort, local software limits, speeds 1–8, device reverse, ambient/chip temperature fallback, manual/automatic modes and two-item temperature compensation. Backlash is hidden.
- Although marked API 3, it is hand-written and still owns a pthread mutex. Property work is queued, but motion completion and recurring temperature work share ad-hoc callbacks without explicit operation ownership/deadlines. The generator column remains No.
- The custom JSON parser accepts loose syntax, ignores trailing garbage, does not require all response fields, uses `atoi()`/`atof()` without full conversion checks, can iterate beyond the ten-element response array, and leaves `qhy_response` scalars/strings uninitialized when fields are missing. Several command helpers log a mismatched `idx` but return success.
- `qhy_command()` discards input before every transaction and reads through `}` without proving exact termination or reserving the NUL explicitly. It treats any positive write as complete rather than requiring the full request length. A per-call command and response buffer are allocated on the stack instead of reusing private storage.
- Serial/TCP open is mostly transactional for handle/global-lock ownership, but successful CONNECTION does not require version, speed, reverse, temperature/voltage or hold-current initialization to succeed. Position is queried twice. The serial path blocks for one second; failure paths and unexpected TCP disconnect scheduling need queue/lifecycle audit.
- The motion callback has no deadline. On a position read failure it sets ALERT, then can immediately overwrite it with OK when stale current equals target. Absolute and relative start failures still schedule completion; a property can stay BUSY or report stale success. Completion uses exact equality without a documented tolerance or progress ownership state.
- Absolute GOTO validates against `FOCUSER_LIMITS`, but relative movement clamps against the fixed `FOCUSER_POSITION` metadata instead of the configured local limit. Relative movement continues after a failed initial position read and zero steps still cause device traffic. Overlapping motion requests rely only on generic BUSY handling and have no explicit cross-property guard between STEPS and POSITION.
- SYNC correctly uses command 11 rather than starting motion, but mixed POSITION/STEPS state updates are duplicated and error paths can leave targets/values inconsistent. Limits are local-only and currently accept values without updating related effective behavior consistently.
- Abort cancels one completion callback, sends command 3 and reads position, but always changes motion properties to OK even when nothing was active and does not distinguish abort/readback/transport failure cleanly. Disconnect calls abort regardless of whether motion is active.
- Reverse and speed propagate direct command failures, but accepted value/target rollback semantics need verification. Mode changes manually delete/redefine properties and change POSITION permission; automatic compensation and the periodic temperature callback can race logically with user motion even though the queue serializes individual callbacks.
- Temperature smoothing uses a five-slot circular buffer with an effective capacity of four. Missing outside sensor (`o_t <= -50`) falls back to chip temperature. A failed temperature command leaves local `temp` at zero and can still invoke automatic compensation. Invalid/no-current samples, threshold transitions, sign, clamping, motion conflicts and failed compensation move/readback lack complete coverage.
- The simulator implements all current command IDs but parses requests with substring search, silently accepts missing/range-invalid fields, truncates oversized replies, does not reject malformed/overlong/trailing JSON, and has no event journal or deterministic split/partial/malformed/wrong-id/silent/transport/stall fault injection. Motion is elapsed in a background thread but does not use the shared `serial_motion.h` model; reverse state and hold-current behavior are not observable.
- The existing integration suite is one broad smoke scenario. It checks representative properties and happy-path commands but mostly waits for any current OK state rather than a fresh revision, does not assert exact JSON/order/readback, and omits parser rejection, transactional initialization failures, polling faults, target-versus-measured progress, no-op/boundaries/overlap, start/abort failure, transport loss, reconnect, external motion, compensation matrix, lifecycle repetition and independent additional instances.
- The simulator and test sources already exist in Xcode and the test Makefile. `REFACTOR.md` and the future `.driver` are absent. A Visual Studio project and solution registration exist, but the project lacks `.driver`/ledger entries and is not registered in `indigo_server.vcxproj`. Visual Studio files must remain absent from Xcode.
- Ignored Windows/macOS build products (`Debug/`, `.obj`, `.ilk`, `.pdb`, `.o`, `.DS_Store` and `.vcxproj.user`) pre-exist in the driver folder. They are baseline workspace artifacts, not source files, and must never be added to projects or treated as refactoring output.

## Rejected-change regression coverage (2026-09-18)

Change requests refused by a busy guard are now declared with the generator's `reject_change` block. The generated guard marks every item for update, sets `INDIGO_ALERT_STATE` and publishes the property with the message, so the client receives the actual driver-side values instead of an `INDIGO_OK_STATE` update carrying no items, which left the refused value visible in the client.

Covered by the `rejected_change` scenario in `indigo_test/integration/test_focuser_qhy_simulator.c`: while `FOCUSER_POSITION` is BUSY, `FOCUSER_STEPS` ends in ALERT with unchanged value and target, no second move command is issued, and motion is accepted again after the abort.

```sh
cd indigo_test && QHY_TEST_FILTER=rejected_change ./build/integration/test_focuser_qhy_simulator
```
