Role: developer. Assigned writer scope was `indigo_test/shell_compliance/indigo_test_framework.sh` and this report only; no entrypoint, driver, generator, build registration, commit or finding-registry writes. Base `66d6815ddc2882895ebc351807977ad008b8274c`; task working tree; macOS with `/bin/bash` 3.2. No physical hardware or live server was used.

## Confirmed baseline

Before source edits, an isolated executable fixture emitted `Device.P.OTHER_ITEM = ON` for list, and `[OK] Device.P.ITEM = ON` then exit 9 for set. Sourcing the original framework with delay 0 demonstrated both defects: `property_exists Device.P ITEM` returned 0 by substring matching, and `test_set_wait_state ... Device.P.ITEM=ON OK 1` printed PASS/returned 0 despite exit 9. The original source was copied to `/tmp/shell-framework-original.sh` for diagnosis only. The independent regression designer retained its broader original-framework baseline in `shell-framework-baseline.txt`.

## Implementation and contracts

- `run_prop_tool OP ...` quotes the executable, inserts the remote options as an array after OP, preserves every argument and the actual exit status, and applies the configured delay directly. `set_remote_server` resets that array when given an empty endpoint. No eval or global pipefail dependency is introduced.
- Query/set helpers capture and check command status before filtering or normalization. Stderr cannot supply a matching successful state. `property_exists` uses exact full-path records and exact item names, returns 1 silently for absence, or records one FAIL on stderr and returns 3 for a failed query. Test prologues distinguish failure from an optional-property skip without double-counting the failure.
- State parsing accepts the actual CLI `-s` format `[STATE]` followed by whitespace and a full item assignment. It requires exactly one item below the requested property, so a similarly prefixed/nested property cannot satisfy a transition. Unsupported legacy fixture-only state syntax is removed. Current GPS fixtures were corrected by the regression writer to real CLI syntax.
- Range helpers request verbose `list -e` for the property, select the exact requested item lhs, and require an anchored numeric value/range payload. Unrelated items, labels and diagnostic ranges do not contribute. Requested strings are passed through ENVIRON instead of awk regexes or `-v` backslash decoding. Both bounds reject non-finite overflow.
- `get_item_number` validates numeric readback shape and rejects empty/malformed/non-finite values, including exponent overflow, while preserving the original valid number text. Ordinary `get_item_value` and text captures retain valid empty text.
- `capture_property_value DEST GETTER QUERY [STATE]` validates a plain identifier, rejects its reserved local prefix, whitelists the four read helpers, checks their status in the parent function and assigns using Bash `printf -v`, without eval. Bash 3.2 does not support printf-v array destinations: entrypoints capture a scalar and then assign an indexed array normally.
- `preserve_connection_state DEVICE TIMEOUT` accepts only ON/OFF snapshots and exposes WAS_CONNECTED 1/0, then installs entrypoint-owned EXIT/INT/TERM traps. `restore_connection_state` restores and verifies the captured value, reports failures and is idempotent after success. The EXIT handler preserves nonzero/signal status, makes a successful exit fail if cleanup fails, and does not restore from command-substitution subshells. The existing battery keeps its original 1-connected/0-disconnected convention and rejects unknown/failed initial-state queries before mutations.
- `test_abort_motion NAME MOVE_QUERY MOTION_PROPERTY ABORT_QUERY TIMEOUT` executes a bounded synchronous wait for BUSY, verifies still-active motion and sends abort immediately. It starts no background process. A move already completed after an observed BUSY is reported SKIP, not asserted as abort coverage. If completion races the abort request and the abort has no BUSY transition, an independently confirmed motion OK also yields SKIP. Failed commands/malformed states do not become skips or passes; a successful exercised case still requires abort BUSY and final OK. The entrypoints retain motion-not-BUSY assertions.
- Summaries retain passed/failed/skipped totals and no longer describe skipped coverage as verified success.

## Developer verification

`/bin/bash -n indigo_test/shell_compliance/indigo_test_framework.sh` and scoped `git diff --check` pass. An isolated Bash-function fixture confirmed numeric 0, -1, .25 and +2.5e3 remain unchanged; empty, nan, inf and 1e999 return status 3 with empty stdout. Exact verbose range selection returned -2.5 and 10e2 despite a different earlier range. ITEM matched while ITE did not. A nested `Device.P.EXTRA.ITEM` state was excluded while the actual `Device.P.ITEM` BUSY state was retained.

An initial current GPS run passed 8/9; the sole failure was a legacy informational sentence missing after a correctly restored ON state. The sentence was restored after successful cleanup. The independent regression writer reported its initial complete new suite had only two fixture-selector mismatches, corrected to reflect actual list-e property selection, and no framework functional failure. Final synthetic full-suite acceptance, six-script required-read integration and post-header checks remain with the coordinator/regression writer; this report does not claim those unperformed final runs.
