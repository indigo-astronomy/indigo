## New candidate findings for coordinator validation

1. **Medium, high confidence: ASTROMECHANICS accepts malformed device measurements as valid sky quality.** `indigo_drivers/aux_astromechanics/indigo_aux_astromechanics.driver:71-75` accepts any positive section-read result and uses `indigo_atod()` without validating a complete numeric payload. `indigo_libs/indigo_bus.c:2727` initializes the conversion to zero and does not return parse status. Reply `garbage\n` to `V#` yields brightness 0/Bortle9 and OK instead of ALERT or preserving last valid data; `17junk\n` similarly becomes 17/OK. The C/Arduino simulator proves numeric-newline reply contract; current inspected integration scenarios exercise valid numeric values and measurement delay, not corrupt reply. Minimal remediation: bounded complete-frame validation and full numeric parse/finite validation at this device-input boundary; add a fake serial malformed-reply regression. Owner: AUX driver maintainer; source proof only, no hardware reproduction. No active finding summary duplicates this issue.

2. **Medium, high confidence: FlipFlat accepts a foreign command reply as success.** `indigo_drivers/aux_flipflat/indigo_aux_flipflat.driver:41-53` returns success solely for positive length and leading `*`. A delayed `*S99000\n` in response to `>LOOO` causes the light switch to publish OK even if the requested light command failed; `*garbage\n` is also accepted. Full C simulator shows distinct `*L...`, `*D...`, `*B...` acknowledgement contracts; Geoptik sibling explicitly checks echoed opcode for exactly this stale/foreign-reply risk. Cover finalizer separately validates its `*S` layout, but light/intensity operations do not. Minimal remediation: validate echoed operation, expected reply shape and payload before accepting operation success; add stale/wrong-opcode tests. Owner: AUX driver maintainer; source proof only.

## Rejected hypotheses and limitations

Do not flag missing generic numeric range validation: framework validates change requests. DSUSB/GPUSB status workarounds intentionally retain documented hardware compatibility, so return-value masking alone is not a new finding without an actual reliable-status hardware failure. Missing explicit finalizer cancellation inside ASI pulse-change code needs generator ownership checked before alleging a race. AO formatted-length overread is existing 3bd2-022.

`indigo_uni_read_section()` passes next-byte timeout -1: first-byte timeout alone does not bound whole replies, especially network input; do not claim partial-frame numeric publication without accounting for its actual blocking/read-zero behavior. This is a concrete follow-up dependency, not a runtime-tested all-driver finding.

3. **Medium, high confidence — PrimaLuce AP mode acknowledgement is ignored.** `shared/primalucelib/primalucelib.c:712-714` returns only `primalucelib_request()` for AP_SET_STATUS; `:302-305` accepts any matching `cmd` verb and request error handling only searches top-level ERROR keys. Reply `{"res":{"cmd":{"AP_SET_STATUS":"Error: invalid command"}}}` therefore returns true. `select_wifi:652-667` propagates success; GIOTTO `:704-728`, ALTO `:869-897` and independently crosschecked focuser `:840-859` memoize the requested switch and publish OK, while readback updates only separate status, leaving X_WIFI wrong. Existing ALTO/GIOTTO simulator `AP_SET_STATUS reject` fault supplies a deterministic reproducer design. Minimal fix: validate named acknowledgement with `primalucelib_reply_is_acknowledged()` and retain error; test rejected AP on/off, unchanged stored state and ALERT. Owner: shared PrimaLuce maintainer. Same acknowledgement weakness in credential/reboot wrappers is related follow-up, not separately duplicated here.

4. **Medium, high confidence — Atik2 failed replacement pulse loses the original stop.** `indigo_mac_drivers/ccd_atik2/indigo_ccd_atik2.driver:427,456` cancels the active axis finalizer before sending the replacement relay mask. On a transient `libatik_guide_relays()` failure the error branch sets ALERT, leaves original relay_mask, and never rearms its original stop. Generated C `:602-641` confirms actual cancellation order, with no hidden cleanup/reschedule. An active 1000ms pulse followed by a failed replacement write may keep the original relay asserted until another explicit command/disconnect. Minimal fix: preserve/rearm the original deadline on replacement failure or perform a verified safe stop. Fake SDK regression should fail one replacement write while a pulse is active and verify the original relay-off still occurs. Owner: Atik driver maintainer; no physical relay measurement.

5. **Medium, high confidence — RPi ROI checks iterators from different temporary maps.** `indigo_optional_drivers/ccd_rpi/indigo_ccd_rpi.cpp:516` returns ControlInfoMap by value; `:1499` compares `.find(&ScalerCrop)` from one copy with `.end()` from another. These iterators do not belong to the same map, so this is not a valid membership test; a camera without ScalerCrop can take the supported-crop branch and get an unsupported control instead of the documented full-frame fallback. Minimal fix: store one local controls map and compare its own find/end; fake profile missing ScalerCrop verifies fallback. Owner: RPi driver maintainer. No platform/hardware runtime.

6. **Medium, high confidence — Andor camera count exceeds the static device array.** `indigo_optional_drivers/ccd_andor/indigo_ccd_andor.c:1434-1435` declares devices[8], but initialization `:1480-1545` and shutdown `:1551-1574` iterate SDK device_num without a cap and access devices[i]. An SDK enumeration of nine valid cameras writes/reads outside the array. README promises up to eight, so excess cameras should be ignored/rejected before allocation and every array loop bounded. Distinct from existing019/020 mutex defects. Fake SDK enumeration with nine devices and ASan is the proposed regression. Owner: optional Andor maintainer.

7. **Low, high confidence — ALTO simulator mutates presets while reporting refusal.** `indigo_drivers/aux_alto/alto_simulator/alto_simulator.c:497-519` updates preset NAME at505 and position at512 even when `refused != NULL`, then emits the refusal at516. `PRESET_1 reject` followed by a valid-name or position set thus returns Error but subsequent get shows changed state, invalidating refusal/rollback test fidelity. DIMLEDS command has analogous write-before-refusal at596. Minimal fix: apply state only when refusal absent and test rejected write preserves state. Owner: ALTO simulator/test maintainer.
