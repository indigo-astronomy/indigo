## Independently confirmed boundary findings

**Native RAW loader — medium security, high confidence, availability defect with unsafe size conversion.** `indigo_drivers/agent_platesolver/indigo_solver.c:598` compares available bytes with `(long)((size_t)header->width * header->height * bytes)` before proving multiplication and signed representability. Width/height are uint32_t (`indigo_libs/indigo/indigo_bus.h:208–212`). On the current 64-bit size_t/long model, header-only RGB48 with width=height=0x80000000 produces unsigned payload 2^63 modulo 2^64, cast to negative long, so zero available payload does not fail this guard. `mono16_image()` at171–176 then receives narrowed signed dimensions and requests 2^63+12 bytes. `indigo_safe_malloc()` (`indigo_bus.h:1043`) asserts or terminates on failed allocation, so this tiny malformed input can terminate its processing process rather than return a parse error. No code-execution claim is established; the exact extreme input is not executed.

Reachability is concrete: CLI `indigo_tools/indigo_solver.c:254–275` reads ordinary file bytes, `:357` calls the loader. Agent `indigo_libs/indigo_platesolver.c:1333–1351` copies positive-size uploaded BLOB content into a task; related-image path at1520–1534 does the same. Framework solve at710–711 calls preview then the backend unconditionally; the backend at `indigo_agent_platesolver.c:542` calls this loader. Preview's `indigo_validate_raw_image()` at framework57–86 only returns from its void preview function and cannot gate backend solving; preview can also be disabled. Thus the repaired common RAW validator does not close this distinct native-loader defect. Existing closed framework RAW-shape022 and active foreign-star-pointer finding are separate contracts. Prerequisite: user opens a crafted file or a client permitted to supply agent image bytes invokes the enabled native solver. Minimal remediation: checked nonzero dimensions bounded by solver int representation, checked pixel/payload/output allocation arithmetic and available-length comparison before any cast/allocation/read; reuse the common validator while preserving solver-specific bounds. Add header-only/extreme-dimension rejection regressions through the public loader and valid controls. Owner coordinator/native solver maintainer; canonical registration requested.

**Bootstrap HTTP downloads — medium security, high confidence.** `tools/cltools.sh:23,35,47` uses unauthenticated initial HTTP for GNU autoconf/automake/libtool archives without pinned hash/signature verification; following configure/make executes their contents and sudo make install can elevate substituted installation code. README230 recommends this script for macOS setup. A network intermediary controlling that first HTTP response can substitute executable source; an eventual HTTPS redirect cannot authenticate the initial reply. This is a developer bootstrap supply-chain trust boundary, not automatic remote compromise of a deployed INDIGO server. Minimal remediation: authenticated initial transport and verified pinned artifact authenticity/integrity before extraction/execution, private temporary workspace and fail-fast download/build handling. No downloads or sudo commands executed. Owner coordinator/build maintainer; distinct from existing release false-status record.

**Andor enumeration — medium memory safety, high confidence, constrained prerequisite.** `indigo_optional_drivers/ccd_andor/indigo_ccd_andor.c:1434–1435` has devices[8], while1480–1545 initializes and writes by unbounded SDK device_num;1551–1574 reads/writes that array during shutdown with the same count. Nine enumerated valid cameras exceed storage. The SDK boundary still requires a cap even though README advertises eight. This is confirmed out-of-bounds source behavior, not a proven remote attack or arbitrary-code-execution claim. Bound the accepted count and all array traversal before allocation/attachment, and exercise nine-device fake-SDK initialization/shutdown under a memory checker in a follow-up. Existing019/020 mutex findings remain separate. Owner coordinator/Andor maintainer.

**Detector failure leaves an indeterminate count — medium functional memory safety, high confidence.** Independently checked native NP05: `indigo_solver.c:820–828` ignores both detector return paths and iterates uninitialized stars_found. `indigo_raw_utils.c:2649` rejects zero geometry;3101–3104 returns INDIGO_FAILED without writing that output. A valid1x1 RAW MONO8 frame plus one pixel, downsample2, becomes0x0 at solver155–167, filtered_image returns NULL, and the failing detector path reaches the indeterminate loop bound. Depending on the indeterminate value, both max_star_count-sized arrays can be exceeded; no exact crash/exploitation outcome is claimed or executed. This is separate from the extreme malformed RAW guard bypass. Initialize the count, honor failure, validate returned capacity and reject zero post-bin geometry; public-loader-to-detector tiny-frame regression should prove a clean no-stars/error result. Coordinator/native solver maintainer owns follow-up and canonical classification.

## Operational and acknowledgement claim dispositions

- **Atik2 replacement failure confirmed, medium functional.** `.driver:418–476` expressly enables accept_while_busy; generated `.c:676–681` uses ANYTIME admission. The existing BUSY exclusion therefore does not reject replacement. Generated handlers602–641 cancel the original axis stop, then on failed libatik_guide_relays set ALERT without rearming the old deadline or verified stop. If that failed write leaves hardware unchanged, the original relay remains asserted without its scheduled stop. Preserve/rearm the deadline or verify a stop; fake-SDK one-failed-replacement regression is needed. No physical output duration or product-safety certification is claimed.
- **FlipFlat acknowledgement candidate confirmed, medium functional.** `.driver:41–53` accepts any positive reply starting `*`, including foreign opcode/malformed acknowledgement; discard-before-write does not prevent a delayed reply arriving after discard. Per-operation acknowledgement shape/opcode is needed before reporting OK. No special exploit claim follows from a misbehaving serial device.
- **Astromechanics malformed numeric reply confirmed, medium functional.** `.driver:71–75` publishes indigo_atod output with OK for any positive received string; conversion has no success contract. This is external device reply validation, distinct from framework-validated client numeric changes.
- **PrimaLuce AP acknowledgement confirmed, medium functional.** `indigo_drivers/shared/primalucelib/primalucelib.c:302–305` matches response verb;712–714 returns transport/request success without named AP acknowledgement validation, propagated by select_wifi652–667. The reported consumer switch state can therefore commit a refused change. This may mislead users about AP-off state, but unproven network reachability/authorization harm is not inflated into a separate security exploit. Validate named acknowledgement and preserve refusal details; coordinator retains combined finding.
