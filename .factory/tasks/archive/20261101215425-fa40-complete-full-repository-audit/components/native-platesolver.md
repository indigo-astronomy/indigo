## Concrete candidates for coordinator classification

### NP01 — RAW extent multiplication can bypass truncation rejection

Location: `indigo_drivers/agent_platesolver/indigo_solver.c:598–635`; native agent consumer `indigo_agent_platesolver.c:542`; RAW uint32 dimensions `indigo_libs/indigo/indigo_bus.h:209–212`.
Severity: medium functional/security boundary candidate; confidence high for guard bypass, downstream exact crash mode not executed. For a header-only RGB48 frame with width=height=0x80000000 on the current64bit host, the unchecked size_t payload multiplication wraps, and conversion to signed long yields a negative payload length. The zero available payload is then not less than the expected negative length; dimensions are also narrowed into signed-int helper/output dimensions. Allocation/conversion follows despite absent pixels, exposing crash/out-of-bounds/oversized-allocation behavior. This is distinct from an older framework RAW-shape fix because the native helper independently parses its bytes and the agent calls it directly.

Safe arithmetic-only evidence (Python3 ctypes, current cwd/revision; no image allocation/conversion/solve): size_t_bits=64, long_bits=64, mathematical payload=27670116110564327424, modulo payload=9223372036854775808, cast long=-9223372036854775808, available payload=0, `0 < signed_payload` is false. Command computes only these integers and `ctypes.c_long` conversion. Follow-up: check dimensions against helper representability, checked multiply and available-byte division before pointer arithmetic/allocation; add bounded malformed-header tests. Fresh independent security review by `/root/full_audit_security` confirms medium denial-of-service exposure and CLI/BLOB reachability; see [security-review.md](security-review.md). The common preview RAW validator returns from a void preview helper and is not a native-solve gate. Root independently confirmed the arithmetic predicate. No malformed image was executed by either reviewer.

### NP02 — documented radius rejection is not enforced on the solution center

Location: README82; agent611–637. Severity low contract candidate; high confidence in missing check, no runtime reproduction. The README says a field outside the hint radius is not solved. The implementation restricts catalog stars to radius plus half-field extent (or full candidate index scale without a scale hint), and after computing a fit checks parity only before setting solved=true. This expanded cone is needed to retain edge stars but does not prove the resulting field center is within RADIUS. A field immediately outside the radius can have all matched stars inside the expanded cone. Existing wrong-position test uses30degrees separation and does not test this boundary. Coordinator should align documented permissive search semantics or add an angular-distance final acceptance constraint if strict rejection is intended.

### NP04 — exported parity comment reverses the actual convention

Location: indigo_solver.h132–135 versus README93–94 and utils radec_to_xy/compute_center consumers. Severity low documentation candidate; high confidence. Header says+1normal/east-left and-1mirrored; implementation and README use+1mirrored/east-right and-1sky/east-left. External helper consumers following the public comment can invert their interpretation. The fit computes `det = a1*b2-a2*b1` at helper1586, `mirrored = det < 0 ? 1 : -1` at1587, and directly writes `*parity = mirrored` at1593. Agent629 passes `&parity`, compares that unchanged value with the hint at630, then assigns it directly to WCS at661. There is no wrapper sign conversion. Utils95–98 explicitly states that its projection uses this same helper/WCS convention. Align the public comment with actual output; no algorithm change requested.

### NP05 — detector failure leaves an uninitialized native loop bound

Location: native helper `indigo_solver.c:818–835`, decoder/binning `:155–167,598–635`, filter minimum dimensions `:793–795`; detector `indigo_libs/indigo_raw_utils.c:2648–2653,3098–3103,3530`. Severity medium functional/memory-boundary candidate; high confidence source proof. `stars_found` is uninitialized at820. Both detector calls discard the returned INDIGO_FAILED, and the loop at828 uses the unwritten count. The new shared geometry validation returns before initializing `*stars_found`; the normal output write is at3530.

Actual bounded consumer trace, inspected without executing a decode or solve: a valid RAW MONO8 header with width=height=1 and one payload byte satisfies the native RAW extent guard. With downsample2, `mono16_image(1,1)` and the one-pixel conversion succeed; `indigo_solver_bin_image()` runs bin_pixels with zero destination width/height, then divides both image dimensions by2, giving0×0. The native filter returnsNULL for dimensions below3. The detector is called with0×0 and immediately fails its geometry check, leaving the caller count indeterminate. Depending on stack/compiler behavior the wrapper can return a fabricated count, read outside all_stars, or write outside the caller star array. Exact runtime behavior is untested. This small trace does not depend on available memory for a giant image and is distinct from NP01's invalid RAW extent arithmetic.

The originally raised large positive geometry is also reachable in source: valid MONO8 width178956971,height1,downsample1 has178956971payload bytes (below INT_MAX), conversion produces representable MONO16 dimensions, the height1 bypasses the filter, and width exceeds INT_MAX/12, so the detector fails without writing its output. No large buffer was allocated. Follow-up: initialize the count and honor detector failure; reject dimensions that become zero after downsampling and preserve a clear failure message. Shared detector callers should not depend on out-parameters after a failure. Root owns the shared API review and finding registration.
