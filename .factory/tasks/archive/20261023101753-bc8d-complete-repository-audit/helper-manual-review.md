## Confirmed functional follow-ups

### H-01 — SX AO simulator fails to clamp its axis limits

Severity: medium; blocking: false; confidence: high; owner: coordinator for assignment.

`indigo_drivers/ao_sx/ao_sx_simulator/ao_sx_simulator.ino:49,58,67,76` uses comparison expressions (`dec == limit`, etc.) where movement-limit assignment is intended. A normal GN/GS/GT/GW request crossing the configured ±50 limit acknowledges L but leaves the stored coordinate outside the limit. Subsequent L status uses exact equality at88-96, so it reports no matching limit bit for that overrun. The west negative branch also names positive limit. Current driver sends the same six-byte directional step commands and consumes the one-byte acknowledgement/limit status. This undermines manual limit/return-to-center testing without proving a physical hardware defect.

Remedy: assign the matching positive/negative boundary after each crossing and verify all four directions, exact limit, first step beyond it, L status and K/R center reset using an isolated firmware fixture/board. No firmware was compiled/flashed or transport opened in this audit.

### H-02 — Sequencer saves a live batch alias instead of a snapshot

Severity: medium; blocking: false; confidence: high; owner: coordinator for assignment.

`indigo_drivers/agent_scripting/library/Sequencer.js:1610-1622` stores `this.saved_batch = property.items`. `boot.js:114-118` updates that exact property.items object in place when the bus delivers changed values. Sequence.focus/focus_ignore_failure at373-384 deliberately expands save_batch→set_batch(1,exposure)→focus→restore_batch. The set_batch acknowledgement overwrites the aliased COUNT/EXPOSURE; restore_batch therefore sends the focus batch values instead of restoring the original capture batch. Source proof follows actual cache mutation and the public focus wrapper; no live agent was changed.

Remedy: copy the relevant primitive batch item values into an independent object and clear/replace snapshots appropriately; test an original batch of several frames with a different exposure, focus success and ignore-failure, then assert restored original values. This is ordinary functional state restoration, not a security assessment of scripting.

### H-03 — Manual Temma firmware replies no longer satisfy driver controls

Severity: medium; blocking: false; confidence: high; owner: coordinator for assignment.

`indigo_drivers/mount_temma/mount_temma_simulator/mount_temma_simulator.ino:215-225` replies R1 to STN-ON/OFF, and235-236 replies R1 to v1/v2. Current maintained `indigo_mount_temma.driver:149-165` requires exact stn-on/stn-off standby status and a v-prefixed version line for speed selection. Normal tracking/standby and high-speed controls therefore fail against this sketch although it acknowledges them. Its configurable STN_ON_MEANS_MOTORS_ON semantics also require reconciliation with the current driver comment that standby ON means motors OFF. The newer host simulator is a separate component; its passing evidence cannot certify this manual firmware.

Remedy: update the manual sketch to the current documented reply/state contract, verify connection/configuration, both standby transitions and both speed transitions with matching command/reply fixtures; retain explicit differences for any documented hardware variant. No manual serial session or board run was performed.

## Limits and candidate dispositions

Arduino serial read timing, EEPROM behavior, actual compiler/library support, WiFi/TCP board configuration and real mechanical/sensor fidelity remain manual verification limits. Fixed test values and protocol subsets are not themselves bugs. PrimaLuce sketch models SESTOSENSO2/MOT1 immediate moves; it cannot certify newer SESTO3/ARCO asynchronous calibration. NexStar AUX acknowledges tracking/manual nonzero commands mainly through diagnostics and does not simulate continuous physics; this explicit subset cannot serve as full motion-readiness evidence.

Perl relay pulse expiry is checked on the next incoming datagram; idle-time physical relay expiry is not modeled continuously. rlchg changes the sensor array instead of relay state; retained as an intended-command-map candidate, without claiming a confirmed exercised driver regression. LX200 idle RA drift uses a different modulus from its manual movement path; retained as coordinate-fidelity candidate pending an explicit intended unit model rather than inventing a hardware acceptance criterion. Neither candidate is silently called fixed or passing.

First-party boot.js cache define/update/delete callbacks, event-device filtering and high-level property type dispatch were read. Sequencer sequence compilation, property completion, pause/abort/recovery/resume, loop/step reporting, time/altitude waits, meridian-flip transitions and camera/mount/dome/guider/solver routing were traced. Pending callbacks across lifecycle transitions remain a meaningful follow-up test surface; no unscheduled broad runtime or live observation sequence was executed.
