the simulator now models the reply observed on hardware.

## Found defects
| Defect | Found by | Impact | Fix | Regression test |
| --- | --- | --- | --- | --- |
| `qhy_parse_json()` returned false on any backslash inside a JSON string, so the `id` field with `\u0019`/`\u0006` escapes made the handshake reply unparsable | user report (reproduced hardware-free with the new simulator reply against the master driver) | the focuser cannot connect: "Failed to connect to Q-Focuser on /dev/ttyACM0" | a backslash and the following character belong to the string; a trailing backslash is still malformed | `capabilities`, `split_transport`, `escaped_id_handshake`, `init_version_escaped_quote` |
| `qhy_parse_response()` required quoted `version`/`bv`; firmware 20231207 sends numbers | source audit of the same report (`"version":20231207,"bv":108`) | the handshake fails even with escapes accepted | `qhy_json_text()` accepts quoted or unquoted field text | `capabilities` (numeric), `quoted_version_handshake` (quoted) |

Both defects were introduced by the generator migration (commit c252b65ec); the hand-written driver before it
accepted the reply. Hardware observation source: the user's server log and pyserial capture quoted in brief.md.

## Manual checks and limitations
- No hardware run: no Q-Focuser available; the hardware reply is modelled from the user's raw capture. The
  quoted-string handshake form (`--quoted-version`) has no hardware evidence; it is kept so the driver stays
  compatible with the form it accepted before (review finding R1).
- Linux and Windows were not run; the change uses only portable C.
- Escapes are kept as received, not decoded; the driver publishes only `version` and `bv`.
