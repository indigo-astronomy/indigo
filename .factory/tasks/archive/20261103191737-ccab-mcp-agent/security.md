## Trust boundary and behavior

The new agent is trusted code consuming untrusted HTTP/UTF-8 JSON over the existing network-wide listener. The existing POST dispatcher is unchanged from its prior independently reviewed content: callbacks receive unread headers/body through the existing PUT-style API, and built-in BLOB/static POSTs cannot become uploads. The new agent must supply its own request policy. No new listener binding, public framework API, driver control, property cache, external process, outbound connection or sensitive filesystem access is added.

The agent registers one exact callback endpoint using existing prefix registration, explicitly rejects suffix/raw-query paths, and responds only to POST; GET has a bodyless 405 rather than a stream. It is disconnected by default and admission/enable state is mutex-protected. No tool reads properties or changes hardware: initialization, ping and an empty tools/list catalog expose only fixed protocol/server metadata. Unsupported tool calls cannot reach the bus. This narrowly bounded state is the basis of the current verdict; absence of authentication must be revisited before data/control capabilities are added.

The existing header preflight remains unchanged. Agent-owned parsing preserves bounded headers, validates field names/control bytes, rejects duplicate Content-Length, any Transfer-Encoding and Expect, requires explicit bounded decimal length/JSON media/Accept types and a valid supported version when required. All Origin-bearing POSTs are rejected for this first headless-only policy. Every response closes the connection, including rejects, so unread/trailing bytes cannot be dispatched as another request. Body progress/total deadlines and eight admitted requests bound stalled body state. Existing socket write timeouts remain; no overall callback preemption is claimed.

The private tokenizer is reused without modifying its existing license/source. Actual JSON acceptance also requires correct separators, literal/number grammar, quoted keys, complete input consumption, valid UTF-8 and paired Unicode escapes, within 64 KiB/256-token/depth-16 limits. Reserved envelope keys are matched after decoding escapes and duplicates are rejected, avoiding alternate-key interpretations. IDs are validated as bounded raw string/lexical-integer tokens and echoed as already validated JSON; response messages and payload fields are fixed literals, not interpolated untrusted format strings. Body/header/response content is suppressed in the agent’s transport logging. Existing server request-line logging remains outside this agent policy; no credentials are placed in URLs or fixtures.

Admission is acquired before body allocation, released on all parsing/response paths, and route removal waits for active callbacks before detaching/freeing the device. No registry/cache/bus mutex is held across network reads or retirement. The agent currently has no bus calls in an HTTP callback, so no new bus-lock inversion was identified. Reload starts from disabled state after previous requests have drained. The existing registration API has no conflict result; this remains a singleton application endpoint rather than a new globally exclusive registration mechanism.
