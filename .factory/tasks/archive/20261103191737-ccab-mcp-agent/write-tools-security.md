# Write-tools security review

Date: 2026-11-04. Independent `mcp_review` subagent, same host/provider, no implementation/test authorship. Separate security pass by the same reviewer as quality review. Candidate identities, functional correction and coverage are retained in [write-tools-review.md](write-tools-review.md).

Verdict: **pass for the explicitly owner-selected visible RW/WO scalar-write boundary**, with FND003 repaired/retested. No separate new security finding identified. This does not certify the whole server or authorize commit, deployment, publication, arbitrary future types or task completion. Earlier skeleton/read reviews remain applicable where unchanged.

## Authorized trust boundary

Enabling MCP exposes visible text/number/switch RW/WO writes, including server and agent controls, to accepted clients that can reach the existing shared listener. The owner explicitly selected that scope and no target denylist, extra authentication or configuration. README/catalog disclose supported types, absent authentication, non-idempotent operations and dispatch-only results. Origin rejection remains a browser-origin restriction rather than authentication. No unrequested restriction or agent-created risk waiver is inferred.

Native access-token checks remain in indigo_change_property. The request token defaults to zero and never comes from cached access_token or helper functions that inherit device/master tokens; an explicit1–16-digit hexadecimal caller token is passed exactly, including all64 bits. No token is echoed in MCP results. BusOK confirms dispatch, not lock acceptance or driver completion. Existing native policy also permits a request token equal to the global master token, including zero if master is unset; therefore default zero is not a new universal lock/authentication guarantee. Full64-bit nonzero-master fixtures verify no automatic elevation and explicit device/master acceptance.

No BLOB/light write, URL fetch, payload encoding, process invocation or file access is added by the agent. Server/agent commands may perform their existing native actions when invoked; their inclusion is deliberate owner scope, not an input-validation bypass. Retries may repeat actions and the tool annotation marks writes destructive and non-idempotent.

## Inspected controls and evidence

Reviewed strict envelope/argument lookup, decoded Unicode target/item matching, duplicate/unknown/type/empty rejection before dispatch, finite numeric conversion and bounded input. Schema lookup only selects visible cached targets; RO/unsupported types fail without bus dispatch. Requests own decoded variable text and contain only submitted items. Cache and service locks are released across bus dispatch so synchronous publications can update the cache; request/snapshot frees occur after ownership ends.

WO definitions retain only schemas; update-to-WO scrubs cached values/history, long text and BLOB addresses/URLs. Lists expose schema metadata and get rejects WO. The former discovery-omission test was amended only for the explicit new contract; value-denial assertions remain. Allocation/cache failure produces an explicit error rather than silently dispatching an unknown schema. Scalar requests and token syntax have no filesystem/process/URL interpretation inside this agent.

Dispatch-thread slots are protected by service_mutex. Same-thread synchronous self-unload returns BUSY before disabling/removing/freeing agent state; native removal honors that result. External route removal retains existing handler drain-before-client/cache/device destruction. This is scoped source reasoning plus deterministic fixtures, not a proof of every possible third-party driver's reentrant behavior.

HTTP callback content logging remains suppressed and MCP adds no token/value log. Existing opt-in native BUS_TRACE logs submitted tokens/text through indigo_trace_property, just as other native bus writers; this review does not claim global log redaction or change core logging. Synthetic fixtures contain no real secret.

FND-20261103191737-ccab-mcp-agent-003 is the confirmed functional numeric-integrity issue described in write-tools-review.md: the old converter could silently dispatch zero for a legal finite number. Reinspected standard-C strtod/current-locale normalization repair and complete-consumption/finite checks; native and sanitizer regression results confirm correction. No OS-specific code/global locale mutation was added. External concurrent setlocale mutation remains unsupported. Coordinator owns canonical finding closure; no residual-risk acceptance is requested for this fixed issue.

Inspected test-writer native30/30 and ASan/UBSan30/30 results, including scaled numbers, comma locale, token locking, WO secrecy, malformed/no-effect cases, self-unload and the retained transport/read regressions.
