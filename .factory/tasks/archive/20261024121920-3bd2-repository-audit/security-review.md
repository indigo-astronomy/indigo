## Validated new security-relevant candidates

1. **High — property copy capacity and prior text ownership (core candidate 1).** `indigo_libs/indigo_bus.c:1618-1635` resizes a reused destination to source active count, then copies the source header including its potentially larger allocated_count. `indigo_resize_property:1605-1613` and `release_dependencies:1640-1662` trust that capacity for writes/frees. `indigo_filter.c:1006` is a live reuse caller. Prior destination long_value pointers are overwritten by memcpy without release. Both capacity corruption and lost ownership are source-confirmed. Fix deep assignment with destination-capacity preservation and cleanup of prior owned text; cover reused destinations with source reserve greater than active count. No matching active finding located. Do not describe every release of every property type as necessarily overflowing: text/BLOB cleanup and subsequent growth/clear are the concrete unsafe consumers.

2. **High — HTTP resource lifetime race (core candidate 2).** `indigo_server_tcp.c:408-424` drops resource_list_mutex then reads the borrowed node and invokes its handler; PUT has the same lookup contract. `:584-616` unlinks/frees nodes while holding only the list lock. `agent_guider/indigo_agent_guider.c:435-436` removes/readds a real file resource during log refresh, so dynamic removal is an ordinary supported operation. Valid use-after-free race; no timing reproduction. Introduce retained response ownership/snapshots, and coordinate handler/module lifetime separately rather than holding the registry mutex over arbitrary I/O. No matching active record located.

3. **High — fixed-size name/text suffix capacity family (core candidate 3).** Source-confirmed examples: `indigo_client_xml.c:44` prepends two characters with sprintf to fixed device->name; `indigo_client.c:443-450` appends service-port suffix after a full-capacity copy; `indigo_filter.c:956-966` concatenates prefixes with names/groups of the same nominal capacity; `indigo_driver.c:1734` appends baud framing after a generic bounded copy; `indigo_ccd_driver.c:820-824` appends directory separator+NUL without reserved bytes; `indigo_bus.c` final indigo_make_name_unique appends suffixes without destination capacity. These are specific capacity-contract failures, not proof that all input names are unsafe. Register a linked family or split by accountable repair boundary. FND-000023 covers separate Raspberry Pi copies and should remain linked rather than silently absorb all core cases.

4. **High — text data reused as printf format (core candidate 10).** `indigo_bus.c:2328,2349` formats into tmp and then passes tmp as another variadic format with no arguments; `indigo_ccd_driver.c:862` passes writable FITS header value directly to indigo_init_text_item; `indigo_agent.c:79-82,97-100` passes source/target name strings as item formats. The existence of raw helper APIs and valid text containing percent characters corroborates the contract mismatch. Header length checks do not remove format semantics. Use raw item setters or constant format when handing off already formatted text. No matching active format-string record was found in the current registry; do not merge into legacyprintf would-have-written-length finding 016, which has a different root cause. Potential memory read/write effects are source concerns, not experimentally demonstrated exploitation.

5. **High — CCD filename expansion/output capacities (core candidate 11).** `indigo_ccd_driver.c` create_file_name has no output-capacity parameter and copies PATH_MAX-based expanded format into smaller caller buffers at :1693/:1791 (callers :2332/:2479/:2561). Independently, :1558-1559 declares buffer2[15] but passes 32 to strftime for a longer normal timestamp; :1605-1609 copies an allowed FITS text into buffer[50]; :1618 permits a full unterminated buffer[15] subsequently used by strcat. These source defects independently justify the finding. Validate expansion lengths and provide destination capacity throughout; do not rely on individual property limits. No matching active filename-engine record located. No file was created and no boundary input executed.

6. **Medium — alignment file count/row validation (core candidate 8).** `indigo_mount_driver.c:425-451` ignores read/sscanf results, publishes an unvalidated count and iterates into alignment_points and property arrays; `indigo/indigo_mount_driver.h:505` has a fixed MOUNT_MAX_ALIGNMENT_POINTS array. A local stale/truncated/corrupt configuration is sufficient prerequisite; no remote attack path is claimed. Parse into temporary bounded state, require complete rows and finite operational values, then publish transactionally. New count/lifetime contract, not existing numeric input validation or image-shape finding.

7. **Medium — PrimaLuce full-token-array traversal (AC-DRV-2).** `shared/primalucelib/primalucelib.c:253-265` accepts any positive jsmn result but discards actual token count; `:374-405` traverses recursively and advances until JSMN_UNDEFINED without an array bound. Full occupancy is allowed by the fixed parser allocation, so the zeroed spare sentinel assumption is not guaranteed. Controller-response overread/availability risk confirmed from source. Store count and bound every traversal/access; include capacity and absent-subtree contracts. Distinct from outbound WiFi escaping FND-000052.

8. **Medium — PrimaLuce firmware concatenation (FM-01).** `focuser_primaluce/indigo_focuser_primaluce.driver:570-573` bounded-copies one value then unbounded-appends separator and second value. `primalucelib.c:416-421` returns a pointer to the reply token without a per-field capacity limit. Valid memory-overwrite candidate on oversized device reply; use one bounded combination. New record, separate from token traversal and FND-000052.

9. **Medium — Alpaca Bayer mapping count/capacity (FM-03).** `agent_alpaca/indigo_agent_alpaca.c:1000-1009` allocates ALPACA_MAX_ITEMS and resets count to zero; `:1210-1217` inserts at count without checking capacity. The nearby main device-number rejection :1186-1198 does not leave the enclosing CCD branch. Independent heap/property capacity issue confirmed; not covered by core registry exact-boundary finding 035. Bound before pointer formation and preserve existing mapping state. No capacity stress executed.

10. **Medium — scripting queued cache pointer lifetime (FM-07).** `agent_scripting/indigo_agent_scripting.c:477-499` mutates/resizes cached property then enqueues its raw pointer; :725 queues the same live pointer for updates; handlers :455-463/:690-698 dereference later. `indigo_driver.c:2221-2229` forwards data unchanged; `indigo_timer.c:1065ff` allocates a queued task carrying that data (no owned property snapshot). Non-BLOB growth reallocates in `indigo_bus.c:1605-1607`. `execute_script:1046-1058` runs ordinary synchronous script operations; queued callbacks do not retain object lifetime merely by carrying device_mutex. Source supports stale-pointer/mutated-notification behavior after valid redefinition. Give queued operations owned stable state or serialize cache mutation in their queue. Distinct from Sequencer.js alias finding 046.

11. **Medium — Pentax reply length/storage/decoding (AC-DRV-9).** `ccd_pentax/indigo_ccd_pentax.c:551-568,582-613,621-655` uses device-supplied uint32 length for VLA, narrows it into uint16 pentax_read (:503), then consumes fixed-offset identity/firmware/model state without a minimum length. scsi_command :399-447 does not preserve/check exact data transfer success/count before returning final CSW status. Device reply can therefore exceed stack budget or invalidate decoded byte extent. New boundary finding, separate from existing unchecked-open020/readiness021. Require bounded heap/storage contract, exact transfer length and checked offset spans; no malformed USB reply supplied.

12. **Medium — PTP descriptor and vendor collection destinations (AC-DRV-11).** Generic `ccd_ptp/indigo_ptp.c:751-814` accepts enum count then indexes fixed numeric storage (PTP_MAX_ELEMENTS=1024; header :325). String decode limits writes to 16 but retains larger count and does not consume excess strings, leaving later indexed consumers inconsistent. Sony extension classifier `indigo_ptp_sony.c:1325-1349` appends based on received payload size to three local fixed arrays without end reserve. Canon `indigo_ptp_canon.c:1036-1074` checks some sizes only with assert, fails to bound group ID against 16 and has unchecked item/list appends. These are actual destination capacity/index defects even where transport is bounded. Register linked descriptor/vendor-destination records or explicitly expand existing PTP019 scope; PTP019 currently names DeviceInfo missing input boundary, so calling all these duplicates without scope change loses evidence. Separate vendor grouping is reasonable for remediation ownership.

13. **Medium — PTP downloaded length discarded (AC-DRV-12).** Generic `indigo_ptp.c:1718-1737`, Sony :1410-1437 and Fuji :379-392 use ObjectInfo size but pass NULL for actual GetObject length and forward metadata size to image/preview sinks. USB allocation :1387-1410 is based on actual container length with 1024 padding, not advertised metadata; `indigo_ccd_driver.c:2610,2629-2632` uses supplied size for file write or BLOB publication. Source-confirmed beyond-allocation read/data exposure risk if mismatch exceeds available allocation; padding does not prove valid extent. No mismatch experiment or disclosure reproduced. Retain actual transfer size and validate metadata separately. Distinct from PTP019 DeviceInfo boundary and imager/Alpaca RAW022.

14. **Medium — Canon outgoing text termination (AC-DRV-13).** `indigo_ptp_canon.c:1534-1540` copies PTP_MAX_CHARS=256 bytes into exactly that available payload then strlen scans for terminator. :1545-1547 passes larger framework text storage. Source overread and potentially oversized outgoing copy validated. Explicit checked encoded length/termination is required. New record, not fixed by inbound descriptor parsing.

15. **Medium — DONUTS algorithm minimum window (MATH-01).** `indigo_raw_utils.c:1237-1248` accepts all positive include dimensions; :1333-1341 allocates power-of-two projection arrays; calibrate_re :1206-1230 always writes first BG_RADIUS+1 entries and starts a trailing write loop at size-BG_RADIUS, which may be negative. Calls :1437-1438/:1458-1459 pass original include dimensions, not padded lengths. For one-wide RGB, :1452/:1456 accesses include_width/height-2. _fft :318-348 also lacks n=1 base case. This is a minimum-domain memory/availability defect, conditional on the existing signal gate, not merely unusual image statistics. Preserve it as a new algorithm-domain record, distinct from prior Bayer/PSF findings. Reject unsupported regions safely or implement small-window behavior; no crash test run. Additional tiny-star neighbor stencil at :2594-2599/:2784-2812 is a related source-supported concern (clip_edge can be zero); registration should preserve its separate neighbor-domain evidence rather than assert every tiny image reaches that branch.
