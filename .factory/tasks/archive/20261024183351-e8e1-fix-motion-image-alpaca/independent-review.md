The expression `3 * size_in * bpp / 8` multiplies size_t by bits-per-pixel before division; MONO16 32768×8192 supplies 512 MiB pixels but intermediate arithmetic wraps to zero, before conversion writes the pixel output. 2. Low, high confidence, corrected during implementation: Alpaca ImageBytes Content-Length `(long)sizeof(metadata) + count * element_size` can overflow signed 32-bit long for an otherwise accepted RAW span near INT_MAX (44-byte metadata versus 12-byte RAW header). Source-byte allocation itself is safe: JSON streams and ImageBytes transmits source byte/uint16 types without int32 expansion. Reported to coordinator and RAW writer; reinspected unsigned-long sum/%lu format in final staged source, sufficient on supported hosts because source bytes are bounded by INT_MAX.
