# Portable agent bootstrap

Use this protocol in any coding assistant or model host. The repository files are the durable project state; a provider's private memory or conversation is not the authoritative handoff.

Read docs/decisions/README.md when present and follow relevant canonical ADR links before reopening a durable decision. For delivery, load [process-checks.md](routines/process-checks.md); inspect the applicable risk policy and task process evidence. These checks preserve existing owner authorization and autonomous routine implementation.

Follow AGENTS.md's persistent-context rule: read the current project snapshot and active task, and load linked historical evidence only when needed. Record this session's reports and history in the task, not shared procedures or project.md.

1. Read root AGENTS.md and applicable scoped instructions for assigned paths. Then read .factory/project.md, state.json, workflow.md, maintenance.json, and the assigned task's state.json (version 2, resolved from task/ID or explicit assignment), plus that task's brief/specification/plan/test-plan/handoff and available review reports. Read active summaries with .factory/scripts/findings list and .factory/routines/findings.md when configured; derive cadence using .factory/scripts/maintenance status in version 2; exclude `.factory/tasks/archive/` and `.factory/findings/archive/` from routine context, recursive searches and scoped-instruction discovery. Open a specific archived task only for a concrete historical question; never resume it solely because its directory exists. Explicitly load the assigned role from .factory/roles/. Load the Git and quality routines when needed; do not assume a host automatically loads role files or nested AGENTS.md.
2. When present, read .factory/template-lock.json and any pending upgrade handoff; follow .factory/routines/template-updates.md for discovery/integration. In an adopted project, missing provenance requires reviewed adoption registration, not a guessed current version. Confirm task ID, current branch/worktree, role, allowed write paths, next action, and any blockers. If new work is needed, act as coordinator to prepare its task branch and task record. If state and the actual repository disagree, reconcile evidence before editing. Never reset state to bypass another active task.
3. Record host/tool name and model ID if exposed (otherwise unknown), available file-read/edit, shell/test, Git, network, and delegation capabilities in handoff.md. Do not infer permissions from the model name. Use equivalent available tools; do not require provider-specific APIs.
4. Use .factory/routines/model-selection.md and the selected provider policy (.factory/openai-model-policy.json or .factory/antropic-model-policy.json) to select a suitable tier; record the reason, actual model/settings if exposed, and any owner-defined budget in the handoff. No automatic switch or API spending is authorized by those files. If a required capability is absent, provide a proposed patch/check or request the missing evidence. Do not mark a proposed command as executed, a suggested patch as applied, or a pasted context pack as a live view. A chat-only assistant can analyze and draft; it cannot verify local execution without evidence.
5. For an assigned cross-provider static review, follow [cross-review.md](routines/cross-review.md) and use `.factory/scripts/review`; the caller remains the only source writer. Project opt-in and host permissions are required. Otherwise follow the shared workflow and English documentation rule. One agent may switch roles sequentially. Delegation requires the host's and owner's applicable authorization; adapter files do not grant it. Preserve security and Git authorization boundaries.
6. Before handing off to another host/model, stop writes and update handoff.md: reviewed revision and dirty state, files changed, current role and phase, exact checks/results, open findings, next action, allowed paths, and the receiving writer. Use a scoped WIP commit when appropriate; otherwise explicitly preserve and describe uncommitted work. Do not switch branches while another tool is writing.
7. The receiving host re-reads shared files and rechecks the actual diff, state, and capability limits. Acquire one writer per task/worktree; a handoff note is a coordination convention, not an enforceable lock. Multiple concurrent agents require separate task/worktree assignments. A model switch does not create a new task or erase findings.

If files cannot be read directly, the owner can provide a fresh local context export from .factory/scripts/context. It includes canonical instructions, the selected role, task evidence, and requested scoped AGENTS.md files. It deliberately omits application source; attach only the minimal reviewed source/diff separately. Treat all excerpts as a snapshot. Check for omitted native tool rules and unresolved decisions before editing. Context is never uploaded by the exporter.
