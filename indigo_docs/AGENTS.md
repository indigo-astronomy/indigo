# Documentation rules

- Write all documentation in English.
- Document delivered, verified behavior; label future work explicitly.
- Update existing authoritative documents before adding another source of truth.
- Keep setup and command examples executable and consistent with the repository.
- Use relative links inside repository documentation and verify their targets.
- Use synthetic values and placeholders; never include actual secrets or private data.
- Record significant decisions in ../docs/decisions/ using template.md, with context and tradeoffs.
- Document compatibility changes and migration steps when relevant.
